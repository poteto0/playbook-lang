# Code Review: c13e4342dcff48562c7679cad7b4c84c6f3a6873

## Summary
Refactored the playbook structure to support multiple actions and improved the quality of parser error messages. Added sequential processing logic to the IR generator to handle multi-phase actions.

## Changes

### Core / AST
- `Playbook` structure now holds `actions: Vec<Action>` instead of a single `action`. This is a breaking change but necessary for multi-phase support.

### Core / Lexer
- Added `Actions` keyword and `LBracket`/`RBracket` symbols.
- Implemented `TokenKind::to_string()` to provide descriptive names for tokens in error messages (e.g., `[` instead of `LBracket`).

### Core / Parser
- Added support for `actions = [ ... ]` array syntax.
- Maintained support for single `action = { ... }` blocks for convenience (they are treated as a single-element vector).
- Improved `expect` method to display human-readable token names in error messages.
- Added validation to limit the number of actions to 3.

### Core / IR Generator
- The generator now iterates through all actions, updating the "current state" (positions and ball carrier) after each phase.
- This ensures that `before`/`after` timings correctly reference the state relative to the specific phase being processed.

### Project / Infrastructure
- Added `ut` recipe to `justfile` as an alias for `cargo test --workspace`.
- Updated `todo.md` to reflect completed tasks.

## Reviewer Comments
- **Quality**: The implementation is robust, and the sequential state tracking in the IR generator correctly handles the complexity of multi-phase movements.
- **Testing**: Excellent test coverage for both success cases (multiple actions) and failure cases (missing brackets, too many actions).
- **Error Messages**: The change to `Expected `]`` style messages significantly improves the user experience.

## Suggestions
- None. The current implementation follows the requested requirements and maintains project standards.
